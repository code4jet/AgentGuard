**7. Current data flow**

Current flow:

1. Static TypeScript constants are declared in [lib/demo-data.ts](lib/demo-data.ts#L1).
2. Server-rendered dashboard imports agents and runs.
3. Client chart components import static chart arrays.
4. Components render values directly.
5. The auth form performs a local timer-based redirect.
6. No user, company, agent, run, result, or report state is persisted.
7. No data is refreshed, streamed, mutated, or loaded asynchronously.

There is no backend data flow.

**10. What should and should not change**

Good and worth preserving:

- Current visual language and brand identity
- Component directory structure
- Shared UI primitives
- Dashboard composition
- Recharts integration
- TypeScript types in `lib/demo-data.ts` as initial domain-model candidates
- Responsive shell and navigation patterns

Must be fixed:

- Missing product routes
- Fake authentication
- No persistence or backend integration
- No agent execution/sandbox
- No trace/result/report workflow
- Hardcoded dashboard metrics
- Dead links and nonfunctional controls
- TypeScript error suppression in `next.config.mjs`

Recommended next step:

Build the backend contract and database model first for workspaces, agents, versions, scenarios, runs, steps/tool traces, classifications, results, reports, and regressions. Then implement `/agents` and `/agents/configure` as the first real vertical slice, followed by scenario generation and test execution.
